# OPERATIONS — التثبيت والتشغيل والصيانة

## 1) المتطلبات

- حساب Google مالك المشروع (نفسه الذي سيشغّل `installSchool`).
- جدول Google Sheets جديد وفارغ (أو نسخة 3.5 للترحيل).
- Node.js ≥ 20 و`npm`، و`clasp` 3.x للتطوير فقط.
- نطاق Google Workspace إن أردت `access: DOMAIN` وSSO.

## 2) إعداد المشروع محليًا

```powershell
npm.cmd install
npm.cmd run vendor
npm.cmd run verify
npm.cmd test
Copy-Item .clasp.json.example .clasp.json
# ضع scriptId الحقيقي في .clasp.json
```

`.clasp.json` و`.clasprc.json` مستبعدان من Git. لا ترفع الأسرار.

## 3) الربط والنشر

```powershell
clasp login
clasp create --title "نظام الحضور والانصراف 3.6" --type sheets --rootDir src
clasp push
```

أو اربط مشروعًا قائمًا:

```powershell
clasp clone <SCRIPT_ID> --rootDir src
clasp push
```

ثم من محرر Apps Script:

1. افتح المشروع المرتبط بالجدول.
2. شغّل `installSchool` مرة واحدة. يعيد اسم المستخدم وكلمة مرور مؤقتة للمشرف الأصلي.
3. انشر: **Deploy ← New deployment ← Web app**.
   - Execute as: `Me (USER_DEPLOYING)`
   - Who has access: `Anyone within <domain>` (أو حسب سياسة المدرسة)
4. افتح رابط النشر، وسجّل الدخول بالمشرف الأصلي، وغيّر كلمة المرور فورًا.

`src/appsscript.json` يضبط المنطقة الزمنية `Asia/Riyadh` وV8 وصلاحيات OAuth. عدّل `access` إذا لزم.

## 4) الترحيل من 3.5

1. خذ نسخة احتياطية من الشيت القديم.
2. اربط المشروع بالشيت نفسه.
3. شغّل `migrateV36` من المحرر بحساب المالك.
4. راجع النتيجة: `cardsCreated`، `duplicateTokens`، `tripsArchived`.
5. افتح النظام وتأكد أن بطاقات الطلاب القديمة ما زالت تعمل.

`migrateV36` لا يحذف بيانات، ولا يغيّر ترتيب الأعمدة القديمة.

## 5) الحسابات والأدوار

| الدور | الصلاحيات |
|---|---|
| `admin` | كل شيء، بما فيه الإعدادات والنسخ والتدقيق والمستخدمون (المستخدمون للمشرف الأصلي فقط) |
| `gate` | لوحة اليوم، المسح، فتح/مسح/تأكيد/إلغاء الرحلات |
| `registrar` | الطلاب والبطاقات |
| `viewer` | لوحة اليوم والتقارير وقراءة الرحلات |

- إنشاء الحسابات من «الإعدادات ← المستخدمون».
- كلمة المرور المؤقتة تُطلب تغييرها عند أول دخول.
- تعطيل حساب أو تغيير دوره أو كلمة مروره يُبطل جلساته.
- لا يمكن تعطيل المشرف الأصلي أو آخر مدير نظام.
- SSO: فعّل «الدخول بحساب Google»، وأضف بريد المستخدم في حسابه. البريد يجب أن يطابق حساب Google.
  إدارة بريد المشرفين مقصورة على المشرف الأصلي؛ مديرو النظام الآخرون لا يرونها ولا يغيّرونها.

## 6) الاستخدام اليومي

1. **بداية اليوم:** تأكد أن اليوم ضمن أيام الدراسة، وأن الطلاب النشطين ظاهرون.
2. **الحضور:** لوحة اليوم ← «حضور» ← امسح البطاقة، أو «الكاميرا»، أو «صورة» لاختيار
   صورة QR من الجهاز. بطاقة 3.5 المطبوعة (STU-1001) تُقبل كما هي. إدخال الرقم يدويًا يتطلب سببًا.
   قارئ USB يعمل كلوحة مفاتيح: ضع المؤشر في حقل المسح ثم امسح؛ لا يحتاج تعريفًا.
3. **الرحلات:** السائقون والرحلات ← «فتح رحلة جديدة» ← امسح بطاقة السائق أو أدخل رقمه.
   المشرف يمكنه اختيار السائق من القائمة؛ المناوب يستخدم البطاقة أو الرقم لأنه لا يملك إدارة السائقين.
   امسح الطلاب فرديًا، راجع القائمة، ثم «تأكيد الرحلة». التأكيد idempotent.
4. **الانصراف:** نفس الخطوات مع «انصراف»؛ لا يظهر إلا الطلاب الحاضرون.
5. **نهاية اليوم:** «إنهاء حضور اليوم» (صلاحية `closeDay`). يُثبّت الغياب ولا يقبل وصولًا بعدها.
6. **التصحيح:** من جدول اليوم، بسبب مكتوب (5 أحرف على الأقل)، ويُسجَّل في التدقيق.

## 7) الصيانة والنسخ

- مشغّل `maintenance_` يعمل كل 10 دقائق:
  - إغلاق تلقائي عند `autoClose` و`closeTime`.
  - نسخة تلقائية عند `autoBackup` و`backupTime` (مرة واحدة يوميًا).
  - إلغاء مسودات الرحلات الأقدم من 48 ساعة، وتنظيف الجلسات.
- «الإعدادات ← النسخ الاحتياطي» يعرض آخر نجاح، والأخطاء، وحالة المشغّل، والملفات.
- «نسخة الآن» ينشئ نسخة ويقلّم الأقدم فوق `retention`.
- «تطبيق سياسة الاحتفاظ» يقلّم النسخ ويلغي المسودات وينظف الجلسات ويبلّغ عن تدقيق قديم.
- الاستعادة تتطلب تأكيدًا نصيًا وتُنشئ نسخة أمان تلقائية.

## 8) استعادة كلمة مرور المشرف

من محرر Apps Script بحساب المالك:

```javascript
recoverSupervisor()
```

يعيد كلمة مرور مؤقتة مرة واحدة، ويبطل كل الجلسات السابقة. لا تُشارك النتيجة في محادثة مفتوحة.

## 9) الأخطاء الشائعة

| الرمز | المعنى | المعالجة |
|---|---|---|
| `SCHEMA_NOT_READY` | عمود/فهرس غير مطابق | شغّل `migrateV36` ثم أعد المحاولة |
| `SESSION_EXPIRED` | جلسة منتهية أو ملغاة | سجّل الدخول من جديد |
| `PASSWORD_CHANGE_REQUIRED` | كلمة مرور مؤقتة | غيّرها من النافذة الإلزامية |
| `PERMISSION_DENIED` | الدور لا يملك الإجراء | استخدم حسابًا مخوّلًا |
| `BUSY` | قفل مشغول > 15 ثانية | أعد المحاولة بعد لحظات |
| `DAY_CLOSED` | اليوم مغلق | لا وصول جديد؛ استخدم التصحيح |
| `ALREADY_CHECKED_IN/OUT` | تسجيل مزدوج | راجع السجل؛ لا حاجة لتكرار |
| `CONFLICT` | تعارض رحلة/بيانات | أعد تحميل الصفحة وراجع الحالة |
| `QR_REVOKED` / `INVALID_QR` | بطاقة ملغاة/غير معروفة | أصدر بطاقة بديلة |
| `STUDENT_NOT_FOUND` | رمز غير مطابق لأي طالب | تحقق أن رقم البطاقة يطابق رقم الطالب في الشيت |
| `DRIVER_INACTIVE` | سائق موقوف | فعّله أو استخدم سائقًا آخر |

إذا لم تفتح الكاميرا: اسمح بالكاميرا للموقع، أو استخدم زر «صورة» لاختيار صورة QR.
إذا لم يقرأ قارئ USB: اضغط داخل حقل المسح أولًا، وتأكد أن القارئ يرسل Enter بعد الرمز.

## 12) تطبيق سطح المكتب — البناء والتثبيت

**المتطلبات:** Windows 10/11 64-bit، Node.js ≥ 20 و`npm` (للبناء فقط).

```powershell
npm.cmd install
npm.cmd --prefix desktop install
npm.cmd run desktop:dist
```

المخرجات في `dist-desktop`:

| الملف | الاستخدام |
|---|---|
| `School-Attendance-Setup-3.6.0-x64.exe` | مثبّت NSIS (المستخدم الحالي، بلا صلاحيات مدير) |
| `School-Attendance-Portable-3.6.0-x64.exe` | نسخة محمولة تعمل من أي مجلد أو USB |
| `win-unpacked/` | نسخة غير محزومة للفحص السريع |

- التطبيق غير موقّع افتراضيًا. عند ظهور SmartScreen: **More info ← Run anyway**.
- بيانات المحمول في `SchoolAttendanceData` بجوار ملف التشغيل.
- بيانات المثبّت في `%APPDATA%\school-attendance-desktop\data`.
- للنسخ الاحتياطي اليدوي: أغلق التطبيق وانسخ مجلد البيانات كاملًا.

### التوقيع الرقمي (اختياري)

`electron-builder` يوقّع تلقائيًا عند توفير شهادة توقيع كود بصيغة PFX/P12:

```powershell
$env:CSC_LINK = 'E:\projects\codesign.pfx'
$env:CSC_KEY_PASSWORD = '<كلمة مرور الشهادة>'
npm.cmd run desktop:dist
Remove-Item Env:CSC_LINK, Env:CSC_KEY_PASSWORD
```

- الشهادة يجب أن تكون **Code Signing** صادرة من CA موثوق (أو شهادة داخلية موزّعة مسبقًا).
- للتحقق بعد البناء:

```powershell
Get-AuthenticodeSignature '.\dist-desktop\School-Attendance-Setup-3.6.0-x64.exe' |
  Format-List Status, StatusMessage, SignerCertificate
```

- `Status = Valid` يعني أن التوقيع سليم ومُوثوق على هذا الجهاز.
- الشهادة الذاتية (Self-Signed) تُظهر التوقيع لكنها لا تمنع SmartScreen حتى تُثبَّت
  في `Trusted Root` و`Trusted Publishers` على كل جهاز، وهي مناسبة للشبكة الداخلية فقط.
- بلا شهادة، يبقى البناء غير موقّع؛ لا تُخزَّن الشهادة أو كلمة مرورها في Git.

هيكل مجلد البيانات:

```
data/                 workbook.json، properties.json، meta.json، drive/
sync/                 ops.jsonl، peers.json، versions.json، hlc.json
backup/               config.json، state.json
backups/exports/      attendance-<deviceId>-<stamp>.json و.xlsx
secrets/              service-account.enc، meta، local.key
logs/                 app-YYYY-MM-DD.log
```

## 13) أول تشغيل والانضمام إلى جهاز

**جهاز أساسي:**

1. شغّل التطبيق واختر «تهيئة مدرسة جديدة».
2. أدخل اسم المدرسة واسم النظام.
3. استورد ملف الطلاب (اختياري) أو أضفهم لاحقًا.
4. احفظ كلمة المرور المؤقتة وغيّرها عند أول دخول. لا تُخزَّن كلمة المرور نصًا في أي ملف؛
   يُحفظ `bcrypt hash` فقط داخل `data/properties.json` تحت `ACCOUNT_<uuid>`.
   عند فقدانها استخدم «نسيت كلمة مرور المشرف؟» في شاشة الدخول لإصدار كلمة مؤقتة جديدة.

**جهاز إضافي (على نفس الشبكة):**

1. شغّل التطبيق على الجهاز الجديد واختر «الانضمام إلى جهاز».
2. من الجهاز الأساسي: «سطح المكتب ← المزامنة ← مفتاح المزامنة» وانسخه.
3. أدخل عنوان الجهاز الأساسي، مثل `http://192.168.1.10:43118`، والمفتاح.
4. بعد الانضمام، يعمل الجهاز مستقلًا وتُدمج تغييراته مع بقية الأجهزة.

افتح منفذ التطبيق (43118–43120 أو المنفذ الظاهر في «معلومات الجهاز») في جدار الحماية
على الشبكة الخاصة فقط. لا تفتحه على الإنترنت.

## 14) المزامنة بين الأجهزة

- الاكتشاف التلقائي عبر UDP، والمزامنة الدورية كل 45 ثانية عند وجود أقران.
- «مزامنة الآن» في لوحة سطح المكتب لمزامنة فورية.
- يمكن إضافة جهاز يدويًا بعنوانه ومفتاح المزامنة إذا منع جدار الحماية الاكتشاف.
- قواعد الدمج:
  - آخر-كاتب-يفوز لكل صف وفق HLC.
  - الحضور: يُدمج `inAt` الأقدم و`outAt` الأحدث بدل تغليب الصف كاملًا.
  - الرحلات: تُدمج بنود الطلاب، والرحلة المؤكدة لا تعود مسودة.
  - الحذف يُسجَّل كأثر (tombstone) لا كمحو صامت.
- لا تغلق الجهاز أثناء أول مزامنة كبيرة؛ انتظر اكتمال العدّاد في اللوحة.

## 15) النسخ الاحتياطي السحابي

1. أنشئ حساب خدمة في Google Cloud وفعّل **Google Sheets API** و**Google Drive API**.
2. أنشئ مفتاح JSON لحساب الخدمة (لا تشاركه ولا تلتزمه في Git).
3. شارك مجلد Drive المستهدف والجدول مع بريد حساب الخدمة بصلاحية تعديل.
4. من التطبيق: «سطح المكتب ← النسخ السحابي ← رفع ملف المفتاح» ثم «اختبار الاتصال».
5. «نسخ الآن» ينشئ نسخة محلية وقواعد JSON/XLSX ثم يحدّث Google.

ماذا يُرفع؟

- جدول Google واحد بتبويبات عربية مقروءة: الطلاب، الحضور، الأيام، التدقيق، السائقون، الرحلات، إلخ.
- نسختا JSON وXLSX محليتان دائمًا في `backups/exports`.
- إذا رفض Google رفع الملفات الثنائية لحساب الخدمة (`storage quota`)، يُحفظ أرشيف JSON
  داخل تبويب `JSON` في جدول Google نفسه، وتظل النسختان المحليتان متاحتين.
- الاستعادة: «استيراد أحدث نسخة سحابية» ينزّل أحدث ملف أو أرشيف إلى النسخ المحلية،
  ثم استخدمه من تبويب النسخ الاحتياطي في الإعدادات.
- النسخ التلقائي اليومي مستقل عن `settings.autoBackup`، ويستخدم وقت النسخ من الإعدادات العامة.

## 16) استيراد الطلاب من ملف

- من الواجهة: «سطح المكتب ← استيراد الطلاب» ثم اختر `.xlsx` أو `.xls` أو `.csv`.
- من سطر الأوامر (أغلق التطبيق أولًا إذا كان مجلد البيانات قيد الاستخدام):

```powershell
# فحص فقط
npm.cmd --prefix desktop run import-students -- --file "E:\projects\بيانات الطلاب.xlsx" --dry-run

# تهيئة نظام جديد مع الطلاب
npm.cmd --prefix desktop run import-students -- --file "E:\projects\بيانات الطلاب.xlsx" --data-dir "C:\SchoolData" --install --school "اسم المدرسة"

# إضافة إلى نظام قائم
npm.cmd --prefix desktop run import-students -- --file "E:\projects\بيانات الطلاب.xlsx" --data-dir "C:\SchoolData"
```

- الأعمدة المطلوبة: رقم الطالب، اسم الطالب، الصف والفصل. الهاتف اختياري.
- تُهمل التكرارات (رقم أو اسم مطبَّع) والسجلات غير الصالحة، ويُعرض تقرير بذلك.
- لا تُستورد أي سجلات حضور تاريخية؛ الطلاب فقط.

## 17) استكشاف أخطاء سطح المكتب

| العَرَض | السبب المحتمل | المعالجة |
|---|---|---|
| SmartScreen يمنع التشغيل | التطبيق غير موقّع أو الشهادة غير موثوقة | More info ← Run anyway، أو وقّع بـPFX موثوق وأعد البناء |
| `SETUP_REQUIRED` | فتح `/api` قبل التهيئة | أكمل شاشة التهيئة أولًا |
| لا يبدأ الخادم المحلي | المنافذ 43118–43120 مشغولة | أغلق النسخة الأخرى أو أعد تشغيل الجهاز |
| لا يظهر أي جهاز في المزامنة | جدار الحماية يمنع UDP/HTTP | اسمح للتطبيق على الشبكة الخاصة، أو أضف الجهاز يدويًا |
| «مفتاح المزامنة غير صحيح» | مفتاح من جهاز مختلف | انسخ المفتاح من الجهاز الصحيح |
| فشل الاتصال بـGoogle | الجدول/المجلد غير مشارك مع حساب الخدمة | شاركهما مع بريد حساب الخدمة بصلاحية تعديل |
| `Service Accounts do not have storage quota` | محاولة رفع ملفات ثنائية بحساب خدمة | يعمل التطبيق تلقائيًا بتبويب `JSON`؛ استخدم OAuth أو Shared Drive لملفات حقيقية |
| نسيت كلمة مرور المشرف | كلمات المرور تُخزَّن كتجزئة bcrypt ولا تُسترجع | من شاشة الدخول اضغط «نسيت كلمة مرور المشرف؟» وأكّد النافذة؛ ستظهر كلمة مؤقتة مرة واحدة |
| بيانات غير متوقعة بعد المزامنة | ساعة جهاز منحرفة كثيرًا | اضبط وقت Windows تلقائيًا، ثم أعد المزامنة |

السجلات في `logs/app-YYYY-MM-DD.log`، والحالة الكاملة في «سطح المكتب ← معلومات الجهاز».
لا ترسل السجلات قبل التحقق من عدم احتوائها بيانات حساسة.

# نظام تحديث التطبيق عن بُعد

التطبيق يفحص عند كل إقلاع (وبزر «فحص التحديث» في لوحة سطح المكتب) ملف
`update.json` على GitHub. إن وُجد إصدار أحدث يظهر تنبيه وزر تنزيل، ثم
«تشغيل المثبّت» الذي يُثبّت فوق الإصدار القديم **دون حذف أي بيانات**.

## دورة إصدار تحديث جديد (من عندك، مرة كل إصدار)

1. ارفع الإصدار في الملفين: `package.json` و`desktop/package.json`، ثم
   `npm test` و`npm run verify`، ثم `npm --prefix desktop run dist`
   (أو التوقيع عبر `tools\build-desktop-signed.ps1`).
2. في مستودع GitHub: Releases ← Draft a new release ← وسم `v3.6.2`
   ← أرفق `School-Attendance-Setup-3.6.2-x64.exe` ← Publish.
3. احسب بصمة الملف:
   ```powershell
   Get-FileHash .\dist-desktop\School-Attendance-Setup-3.6.2-x64.exe -Algorithm SHA256
   ```
   وضعها في `sha256` (أدنى بسيط، وتُرفض الحزم المخالفة تلقائيًا).
4. عدّل `update.json` أعلاه (الإصدار + رابط Release + الملاحظات) وارفعه
   في مساره `docs/update/update.json`.

المسار الافتراضي الذي يقرؤه التطبيق:
`https://raw.githubusercontent.com/AmmarIzzeldin996/School-Attendance/main/docs/update/update.json`
ويمكن تغييره بمتغير البيئة `SCHOOL_ATTENDANCE_UPDATE_URL`.

## ما يفعله المشرف في المدرسة (دون حذف القديم)

1. «سطح المكتب ← المزامنة والنسخ الاحتياطي ← تحديث التطبيق».
2. «فحص التحديث» ← «تنزيل التحديث 3.6.2» ← «تشغيل المثبّت».
3. أغلق التطبيق عند مطالبة المثبّت. البيانات في `SchoolAttendanceData`
   أو `%APPDATA%` لا تُمس؛ سجل الدخول والإعدادات والمزامنة كما هي.

لعدة أجهزة: حدّث الجهاز الأساسي أولًا ثم البقية؛ المزامنة تتقبل اختلاف
الإصدارات المؤقت، فلا تعطّل العمل إن تأخر جهاز.

## ملاحظات أمان

- الرابط `https` فقط واسم الملف يجب أن يكون `*.exe` وإلا يُرفض البيان.
- إن وُجدت `sha256` في البيان وتخالفت بصمة الملف المنزّل، يُلغى الحفظ فورًا.
- فحص وتنزيل وتشغيل المثبّت محصور بمسارات `/desktop/*` التي تتطلب جلسة مشرف،
  وفتح الملف عبر IPC مقصور على `.exe` داخل مجلد `updates` لمجلد البيانات.
- المثبّت موقّع بشهادتك الداخلية؛ أبقِ `trust-internal-signing.ps1`
  مثبتًا على أجهزة المدرسة كي لا يظهر تحذير SmartScreen.
